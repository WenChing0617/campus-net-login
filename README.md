# 校园网自动登录（Edge / Chrome 扩展）

在**每天固定的时间点**自动完成校园网门户认证，循环执行。扩展平时完全休眠，**不做实时轮询**，只在四个时机动作：定时到点、浏览器启动、错过补偿、认证页被打开。

## 1.14.0：本校开箱即用 + 认证周期（每 N 天）+ 去掉个人信息

- **新增「认证周期（天）」**：设置 → 定时认证 → 认证周期。`1` = 每天（默认，一天里填的几个时间点都跑）；
  填 `N` 就是**每 N 天认证一次** —— 上次认证之后中间 N-1 天直接跳过，到第 N 天的时间点才再跑。
  给移动 / 联通这类「认证一次能撑好几天」的运营商用，省掉每天白开一次页面。
  手动点「立即认证」「打开认证页」不受周期限制；
- **本校开箱即用**：门户地址 / 备用入口 / 校内业务域名按 Anhui Polytechnic University 预填好，换学校改三处即可；
- **不再预置学号**：账号留空，装好后在设置页填一次；
- **服务商默认中国电信**（唯一长期每天在跑的一家，移动 / 联通选项保留但不保证细节一致）；
- **门户判定跨校通用**：不依赖某个学校的域名，改成「强特征 + 按页面内容的排除词」，换学校一样有效；
- **弹窗里的学号打码**：只显示首尾各两位（`32*****28`），不再整串摆出来；
- 删掉了早先那套脱离浏览器的独立脚本（headless Edge 方案）。

## 1.13.0：不再误伤教务系统这类校内站点

**现象**：打开教务系统这类校内业务登录页（例如 `http://jwxt.example.edu.cn/login.action`）时，扩展会突然弹一条通知，然后把网页自己关掉。

**原因**：教务系统同样挂在 `.edu.cn` 下、同样有账号密码框、页面上同样写着「用户名 / 密码 / 登录」。旧版判定「是 `.edu.cn` + 像登录页」就当成校园网门户 → 填表提交 → 后台按「认证成功」收尾 → 关掉**你自己开的**标签页。

**现在的三层防护**：

1. **强特征**：不是设置里那个门户、也不是自动发现到的门户时，`.edu.cn` 页面必须出现「校园网 / 上网认证 / portal / srun / ac_id / 运营商 / 选择服务 / 我要下线…」这类**只有校园网认证页才有**的词才放行，光有「账号密码登录」不算；
2. **排除词**：页面出现「教务 / 选课 / 成绩 / 图书 / 一卡通 / 统一身份…」直接否决；
3. **排除域名**：设置 → 认证页入口 → 「排除域名」。默认按本校列好了教务 / 图书馆 / 邮箱几个域名；换学校请改成自己学校的，或者清空（跨校通用的第 2 条「按页面内容」始终生效）。写 `jwxt.example.edu.cn` 只排除它一个；写 `example.edu.cn` 会连门户一起排掉，慎用。

另外**关页面也收紧了**：只有**扩展自己打开**的标签页才会被自动关掉；你自己打开的页面（包括自己输地址打开的门户页）认证完会留在那儿。

## 主要适配：Anhui Polytechnic University（安徽工程大学）

这个扩展是照着**本校 Anhui Polytechnic University（安徽工程大学）**的校园网门户调通的：
网关自动跳转 + SPA 门户（Angular + ng-zorro）+「服务选择」独立整页 + 运营商 **中国电信**。
门户地址、备用入口、校内业务域名（教务 / 图书馆 / 邮箱）都已按本校预填，
**本校同学装上、填一次密码就能用**。

- **运营商**：默认中国电信，也是唯一长期每天在跑的一家。中国移动 / 中国联通的选项保留着，
  门户上真出现这两家时扩展会用同样的办法去选，但作者没有长期使用过，**不保证细节一致** ——
  这两家通常是「按天」续期的，配合下面的**认证周期（每 N 天）**用正好；
- **别的学校**：套路是通用的（网关 302 → 门户页 → 登录表单 → 服务选择 → 确定），
  所以别校大概率也能直接跑；但作者只对本校有把握，别家没逐一验证过。
  换学校改三处即可：认证页地址 / 备用入口、排除域名、服务商；
- **不预置任何人的学号 / 账号**，装好后在设置页填一次。

默认走「让网关自动跳转」，扩展自己探测门户地址，所以**一般不用手填地址**；
典型的校园网认证入口是网关动态生成的：未认证时访问任意 http 网站，网关会把你 302 到
`portal.example.edu.cn/portal/portal-main?sessionId=…&userIp=…&userMac=…`，这一页再跳进登录界面。

只有少数情况才需要手填门户地址（网关不跳转、或门户入口写死）：设置 → 认证页入口。

```
每次认证前先探一次网络（fetch 检测地址，每个地址最多等 1.5 秒，只有 204 才认「真的通了」）
  ├─ 确认已联网（204）→ 直接收手，一个标签都不开（不会留下「无标题」的空白检测页）
  └─ 否则 → 按顺序试入口，哪个能刷出登录表单就用哪个：
             ① 探测到的门户地址（自带 sessionId / userIp / userMac）
             ② 备用入口（设置里填了才用）
             ③ 手填的认证页地址
             ④ 检测地址（让网关自己 302 跳过去）
  → 门户口页面按「上一轮认证有没有到期」分两路（1.11.0）：
      ├─ 还没到期 → 不给登录表单，直接渲染「已在线」成功页（上面有「我要下线」）
      │    → 点「我要下线」→ 点确认弹窗 → 门户注销并跳转
      │        ├─ 落回认证页 / 服务选择页 → 把下面这套认证流程**重头做一遍**（认证时长这才真正从这次续上）
      │        └─ 落到「已下线」页 → 点「重新入网」→ 回到认证页，继续往下
      │             （认不出 / 点不动那个入口 → 照门户自己的做法跳到它的重新入网地址，见 1.11.1）
      └─ 已到期 → 门户正常渲染出登录界面
  → 进页面立刻填账号密码 → 点「立即登录」
  → 服务选择：可能是同一页弹窗，也可能是**整页跳转**到
     /portal/entry/pc/serviceSelection;flowParams=undefined;from=authenticate;sid=false
     （这一页没有密码框 —— 扩展会自动「从选服务这一步直接进场」）
  → 选中你在设置里选的运营商 → 点「确定」
  → 若弹出「portal认证失败」提示 → 点「我知道了」→ 重新选服务 → 再点「确定」
     ↑                                              │
     └──────────────────────────────────────────────┘
  → 「明确成功字样」/「**跳转到最终界面**」/「204 探测确认」→ 判定成功 → 发通知 + 关页面
```

- **入口一条链，四个都试**：网关跳转失效、门户换了地址、检测地址被拦成 200 的拦截页……都会自动换下一个入口，不会「打不开就干等着」。
- **不让任何一次请求把流程拖住**：探测用的 `fetch` **每个地址最多等 1.5 秒**，连挂两个就直接收手——不在校园网、或学校把探测地址全屏蔽时，旧版会一路挂着等 TCP 超时（一个地址十几秒），这正是「点了半天没反应」的原因。
- **等页面就绪不再反复注入脚本**：前 6 次用 400ms 的短间隔探，之后才放慢到 1 秒；内容脚本本来就由浏览器自动注入，不再每轮 `executeScript` 一遍（那是给「等待」本身加几百毫秒）。
- **不进页面先探网络，但结论很保守**：只有检测点返回 **204**（或两个不同来源都确认通）才认「已联网」。网关拦截时回的那个 **200 拦截页不再被当成联网**（这正是旧版「明明掉线却说无需认证、一个页面都不开」的根因）。
  ⚠ **但探测结论从此只用来「找门户地址」，不再用来跳过整个流程**（1.12.0）：认证没到期时网络本来就是通的，
  那句「本次无需认证」恰恰是假结论 —— 它让后台连页面都不开，页面脚本也就没法去跑「已在线 → 下线 → 重新认证」。
  所以**定时到点**或**手动点认证**都会真的打开门户页（已经认证过时还会跳过网关检测地址、
  直接进门户自己的页面，因为那个检测地址在已认证状态下只会是一张空白页）。
- **进页面就填**：认证页一出现密码框就立刻写账号密码，不等后台下发指令。
- **「服务选择」是独立整页也照样自动选**（1.8.0 新增）：本门户点完「立即登录」会**整页跳转**到
  `/portal/entry/pc/serviceSelection;flowParams=…`，那一页里**没有密码框**，只有服务选项。
  扩展现在把这一页当成一个**独立的进场点**：地址里带 `serviceSelection` / 页面上写着「请选择服务」/
  页面上真的露出了运营商选项，命中任一就认，然后直接执行「选运营商 → 点确定 → 看结果」。
  后台也认这个落地状态（不会再把「没有密码框」误判成「打不开登录表单」而反复换入口重开），
  并且万一页面脚本没动，后台会补发一次「去选服务」指令（**每个流程只补一次**，不会重复提交）。
- **服务商怎么都能选中**（1.7.0 重做 + 1.8.0 加兜底）：不再挑门户的写法。`radio + label`、被 `opacity:0` 藏进卡片的单选框、纯 `<div>/<li>` 卡片列表、文字放在 `<b>` 里……全都认。判定「服务选择界面在不在」时会**连祖先容器一起看**（卡片可见就等于界面还在），不再因为「元素自己不可见」就误判成「没有服务选择界面」而直接放弃。选中动作是**能点的全点一遍**：radio 原生选中 → label → 文本元素 → **再逐层往上点祖先容器**（最多 5 层），任一时刻「页面标记为已选」或「确定按钮变亮」就算成事。都认不出来时还有**最后一招「整页粗搜」**：页面上哪里写着「中国电信」，就把那一块和外面几层小容器点一遍（也就是最早那版能选上的朴素做法）。点「确定」弹窗却没反应时，会自动重新选一遍再提交（最多 6 次）。
- **按门户的「真实结构」重做了「找按钮 / 找选项」**（1.9.0 —— 这是「服务选择界面不动」的真正根因）。把门户的前端代码拆开看，这一页是这样：
  选项 = `<div class="service-box"><span class="service">中国电信</span></div>`（**整页没有 radio、没有 label、没有 input**），
  「确定」= `<div class="footer"><button>重新登录</button><button>确定</button></div>` 里的那个 `<button>`。
  旧版的两条识别正好都栽在这里：
  ① 找「确定」是按文字找的，**包着两个按钮的 `<div class="footer">`**（文字＝「重新登录确定」）拿到 45 分刚好过线，被当成了确定按钮 ——
    脚本于是自以为「确定可以点了」，提前结束选服务；真要点的时候又点在容器的 `<div>` 上，而门户的 click 监听挂在 `<button>` 上，**收不到**。
    表现出来就是「点了也没反应、界面不动」。
  ② 包着三家运营商的容器 `<div id="relationInfo">`（文字＝「中国电信 中国移动 中国联通」）被当成了「中国电信」的候选，
    第一次点击点在这个容器上，什么都不会发生 —— 运营商其实一个都没选中。
  现在：**容器一律降权**（自身不是原生按钮、里面还包着按钮的，直接排到真按钮后面），**运营商候选只认「只出现一家」的元素**。
  门户的按钮文案全走 i18n（`select.a.service` / `sign.in.again` / `ok`），翻译没加载时页面上会直接显示键名，这些键名也一并认上。
- **门禁把页面挡住时不再一声不吭**（1.9.0）：开关关了、暂停中、站点不在允许范围……旧版都是**静默 `return`** ——
  页面停在「选择服务」上，扩展什么都不做也不说，看起来就是「不动」，这正是最难查的那种故障。
  现在会往弹窗状态里写一条看得懂的说明（例如「停在『选择服务』页面但扩展没有操作：设置里关掉了进认证页自动填写」）。
  另外「设置里运营商没填」也不再原地不动，退到默认「中国电信」试一次；服务选择页只可能出现在校园网门户里，**直接放行**，不再被文本特征判定挡在门外。
- **「跳转到最终界面」就算完成**（1.10.0 —— 主人这轮的要求：「节省时间，避免关闭认证页和通知延迟」）。
  以前点完「确定」还要等两件事才算完：要么页面上出现「认证成功」这类字样（门户不一定写），
  要么后台探一次网络拿到 204（快也要几百毫秒，慢要几秒）。于是页面早就好了，**通知和关页面却慢半拍**。
  现在改成：**点过「确定」之后只要离开流程页（登录页 / 服务选择页），就立刻认定认证完成**。
  这条判据的底气来自门户自己的代码 —— `ServiceSelectionModule.submitForm()` 只在
  `serviceLogin` 返回 `authResult==='success'` 时才 `nextPath()` 跳走；失败时只弹一个提示弹窗、**地址一动不动**。
  所以「点过确定 + 地址真的变了 + 页面上再没有登录表单/服务选项/确定按钮」＝ 门户已经把我们推到下一节点。
  两条安全边界：**没点过「确定」时地址变化不算**（入口页本身也不是流程页地址），
  **被退回登录页（还有密码框）不算**。判据同时写在页面脚本和后台 `tabs.onUpdated` 里，
  整页跳走（脚本被销毁）的那条路也能立刻收尾。
- **认证还没到期也能续期**（1.11.0 —— 主人这轮的要求：「有时到认证时间可是认证还没到期，则是直接进入 … 进行下线，然后认证」）。
  到点时如果上一轮认证**还没到期**，门户的行为是：**不给你登录表单**，直接渲染一张「已在线」成功页
  （`app-login-success`，地址是 `entry/pc/finish;flowParams=undefined;from=`），上面有一张功能卡片叫「我要下线」。
  旧版碰到这一页只会把它当成「本来就在线」→ `skipped` 收手，于是**认证时长一直没续上**，下次到点又是在线，恶性循环。
  现在这一页被当成一个**独立的进场点**，走一条专门的支路：
  点「我要下线」（只认功能卡片里 `.fun-name` 的短文，排除「重新/再次」这类）→ 在 `.ant-modal` 里点确认弹窗的「确定」（只认 ok 按钮，排除取消/关闭）
  → 等门户注销并把页面跳走（最多 9 秒）：
    · 落回认证页 / 服务选择页 → **把整套认证重头做一遍**（这才是「续期」真正生效的地方）；
    · 落到「已下线」页（`app-account-offline-success` / `app-sid-success`）→ 点它上面那个按钮回到认证页再认证。
      那个按钮的文案是门户 i18n 的 `Reconnect.network` —— **中文就是「重新入网」**（见下条 1.11.1 的事故）。
  开关是设置里的 **「到点时若上一次认证还没到期…先点『我要下线』再重新认证一次」**（默认开），关掉即回到旧的「已在线就跳过」。
  两个配套细节：页面脚本会顺手往后台报一个 `relogin` 标记，后台据此开 **90 秒宽限期**——
  因为下线重认证这段时间网络本来就是通的（探测会回 204），**不能让后台拿一次探测就把流程半路收尾**；
  另外「已在线 / 已下线」两种页面**都没有密码框**，跟服务选择页一样会被「该框架没表单，让开」的规则误伤，所以它们也一并归进「这一页有活要干」。
- **「重新入网」文案事故 + 跳转兜底**（1.11.1 —— 主人这轮：「未点击重新入网，保存设置认证也要进入网页」）。
  1.11.0 犯了一个很隐蔽的错：我把 `Reconnect.network` 按英文键名**意译**成「重新连接网络」写进了词表，
  而门户语言包（`assets/tmp/i18n/zh-CN.json`）里它的真实中文是 **「重新入网」**。
  结果就是：真机上注销完落到「已下线」页，扩展**一次都没认出那个按钮**，页面停在「已下线」不动、
  认证也没进到网页里（自测全绿是因为测试里的模拟页也照着我那个错文案写的 —— 拿假设去验假设）。
  现在：① 词表照语言包抄齐（`重新入网` / `重新认证` / `重新登录` / `已处理，重新入网`，长度上限也放到 16 字）；
  ② 「已下线」页多认一个组件名 `app-sid-success`；③ **认不出、点不动都还有一跳兜底** ——
  照门户自己的实现（chunk 7243 / 9903 / 4457）跳 `localStorage.samPortalRedirectUrl || 协议 + '//2.2.2.2'`，
  由网关带着参数把我们送回认证页；用 `sessionStorage` 做 20 秒打转守卫，不会来回弹。
- **认证一定真的进网页**（1.12.0 —— 主人同一句要求的后半段：「保存设置认证也要进入网页」）。
  接上一条修完之后在真机上仍然没反应，顺着链路往回查才发现**页面脚本压根没机会出场**：
  后台在打开页面前会先探一次网络，认证没到期时探测必回 204，于是后台一句「网络正常，本次无需认证」就收手，
  **一个标签都不开**（这条当初是照「别留空白检测页」的要求加的，没想到反过来把续期这条路堵死了）。
  所以 1.12.0 的改法是**把「要不要跳过」的决定权从后台收回来**：
    · **定时到点 + 开着续期** → 不再跳过，照常打开门户页；
    · **手动点「保存并立即认证一次」/「打开认证页」** → 无条件打开，这是主人明确按下按钮的意思；
    · 已经认证过时**跳过网关检测地址**直接进门户自己的页面（那个地址在已认证状态下只会回一张空白页，白等十几秒）；
    · 页面 PING 回「这一页看着像已在线」时，也不再当场照搬「本来就在线」收尾关页，而是把指令发下去让页面自己判断。
  兜底仍然安全：页面怎么都刷不出来时还会再探一次，确认网络真通就**悄悄把标签关掉**、只记一句「本次无需认证」，不留垃圾窗口。

- **「成功」判定收紧**：必须真的出现「认证成功 / 已在线」这类字样，**或**地址已经跳离流程页，**且**密码框、服务选择弹窗、「确定」按钮都已消失。页头那种「已连接」「注销 / 退出登录」到处都有的词**不作数**；判定不出来时只算「待确认」，要等网络探测（204）点头才收尾——**不会在服务还没选完时就把页面关掉**。
- **卡住时留下现场**：弹窗底部会显示**页面诊断**（当前路径、几个 radio、各自 value/id/label/父容器、候选运营商、按钮清单、**页面骨架**）**和一小段原始 HTML**，点一下即可复制。把它们发过来就能直接定位门户结构，不用再猜。
- 失败后的重试路径是 **「我知道了 → 重新点确定」**（不需要点「重新登录」，也不会重填账号密码）。
- 失败重试最多 **3 轮**，超过就停下。
- 账号密码**全程只提交 1 次**，后续重试都用「确定」。
- **系统通知只留「成功」那一个**：认证失败不弹、本来就在线无需认证也不弹。
- 若提示里出现「已在线 / 重复登录」，直接判为成功，不会傻乎乎地反复登录。
- **默认值是通用的**：账号密码留空（装好后在设置页填一次）、入口模式「让网关自动跳转」、门户地址与备用入口留空（扩展自己探测）。服务商默认「中国电信」，可改成中国移动 / 中国联通。
- **只有密码需要你自己填一次**（见下），我没有把密码写进代码文件里。
- 弹窗里有一个 **「打开认证页」** 按钮：不管探测怎么说，都把门户页面直接开出来（等价于你手动打开网页那条路，只是页面会自己填好表）。

| 时机 | 说明 | 开关 |
| --- | --- | --- |
| 到达设定时间点 | 每天循环，如 08:00 / 12:30 / 18:00 | 定时认证 |
| 浏览器启动 | 打开浏览器时补认证一次 | 浏览器启动时认证 |
| 错过时间点 | 电脑关机错过了认证时间，下次启动补一次 | 错过则补偿 |
| 打开认证页 | 你或计划任务打开认证页，自动填表提交 | 自动填表 |

## 后台开销与认证速度

- 非认证时段：**零轮询、零定时任务**，只有一个「下一次认证」的一次性闹钟。
- 每次认证：先探 1 次（**单次探测 + 每个地址 1.5 秒超时**）；**已联网就直接结束**（不开标签、不通知），掉线才提交 + 复查，合计 2～3 个请求。
- **任何一次网络请求都不会把流程拖住**：探测带超时；门户页的等待改成「前 6 次 400ms、之后 1 秒」的探询，页面一好就立刻往下走。
- **不会留下空白页**：以前每次认证都无条件打开一个检测地址标签，网络本来就通时那个页面就是「无标题」的空白页；现在先探测，联网时连标签都不开。
- **认证页一打开就填，不等后台催**：内容脚本自己读本地配置，密码框一出现就立刻写账号密码（晚渲染的门户由 DOM 监听在几十毫秒内补上），省掉了「上报后台 → 后台注入 → 下发指令」整圈往返。
- 页面内每步都是**轮询等状态**而不是固定等待：按钮一可用就点、弹窗一出现就处理，不再有「明明好了还要干等 1.5 秒」。
- 从点「确定」到出结论通常 **2～4 秒**；一有结论立刻收尾，**通知先发、再关页面**（关标签本身也要时间）。
- **认证成功后门户常常整页跳到 `redirectUrl`**，这一跳会销毁页面脚本、让它来不及回报。后台现在盯着登录标签的地址变化，一旦跳离门户域就立刻探测，**约 0.6 秒内**把结果捡回来 —— 这是之前「认证完半天不关页面、通知迟迟不来」的根因。
- 同一轮认证只收尾一次：不会出现重复通知、重复关页面。

1. 打开 `edge://extensions/`，左下角打开 **开发人员模式**

> 想立刻试：弹窗里点 **立即认证**，然后盯着那个认证页标签，应该能看到它自己填、自己选、自己提交。

## 常用设置

| 设置项 | 说明 |
| --- | --- |
| 认证页打开方式 | **让网关自动跳转（推荐）** / 直接打开填写的地址。前者不猜地址、参数永远有效；两种模式都会依次试多个入口 |
| 备用入口地址 | 默认 `entry/pc/finish`。前面的入口都刷不出登录表单时再试它；学校门户换地址了改这里 |
| 认证时间点 | `08:00,12:30,18:00`，24 小时制、逗号分隔，循环执行 |
| 认证周期（天） | **1 = 每天**（默认，一天里几个时间点都跑）；填 `N` 就是**每 N 天认证一次**——上次认证后中间 N-1 天跳过，到第 N 天的时间点才再跑。给「认证一次能撑好几天」的运营商用。手动点「立即认证」不受它限制 |
| 浏览器启动时认证 | 开浏览器就跑一次（确认已联网时自动跳过） |
| 错过则补偿 | 电脑关机错过时间点，下次启动补一次 |
| 放宽探测判定 | 默认关。开着会让「非 204 的单一来源结果」也算已联网——只有确认学校不会屏蔽探测地址时才开 |
| 已在线时先下线再认证 | **默认开**。到点时若门户直接显示「已在线」页（上一轮认证还没到期、门户不给登录表单），先点「我要下线」+ 确认弹窗，等门户注销跳回认证页后把整套认证重做一遍，让时长真正续上；关掉则退回旧的「已在线即跳过、不碰页面」 |
| 认证成功后关闭认证页 | **默认开**。一有结论就关，不挂页面 |
| 关闭触发标签页 | 配合计划任务用：任务拉起浏览器 → 认证成功 → 标签页自动关掉 |
| 系统通知 | 只在**认证成功**时弹一条；失败、以及「本来就在线」都不弹 |

账号密码只存在浏览器本地（`chrome.storage.local`），不上传任何服务器，扩展不含远程代码；但密码是**明文存储**的，共用电脑请谨慎。

## 「浏览器没启动 / 电脑锁着」怎么自动登录

浏览器扩展只能活在浏览器里。**浏览器没运行时，扩展本身无法执行任何操作**。

思路只有一条：**让系统先把浏览器拉起来，再由扩展接手**（扩展只能活在浏览器里）。
两条路，挑一条：

### 方案 A：让 Edge 自己打开认证页（最简单，零脚本）

1. `edge://settings/onStartup`（设置 → 开始、主页和新建标签页）
2. 选 **打开以下页面** → **添加新页面** → 填认证页地址（不知道就填 `http://connectivitycheck.platform.hicloud.com/generate_204`，未认证时网关会把它跳到认证页）
3. 扩展设置里把 **认证成功后也关闭「触发认证的那个标签页」** 打开

之后只要你打开浏览器，认证就自动完成，页面也会自动清理掉。适合「每天都在用电脑」的情况。

### 方案 B：Windows 计划任务定点拉起浏览器（电脑/浏览器都不用管）

用 `tools/` 里的两个脚本，在你设定的时间点自动启动 Edge 并打开触发地址，扩展接手认证，成功后自动关掉标签页。

```powershell
# 在你自己的账户下运行即可，不需要管理员权限
powershell -ExecutionPolicy Bypass -File tools\setup-scheduled-tasks.ps1 -Times "08:00,12:30,18:00"
```

参数：

| 参数 | 说明 |
| --- | --- |
| `-Times "08:00,12:30,18:00"` | 时间点，写几个就建几个任务（`CampusNetLogin_0800` 这种命名） |
| `-Url "http://10.0.0.55/srun_portal_pc?ac_id=1"` | 触发地址，默认是 204 检测点；知道认证页地址就填 |
| `-Wake` | 到点自动唤醒睡眠中的电脑 |
| `-Remove` | 删除已建的全部任务 |
| `-DryRun` | 只打印将要做什么，不真的创建（先跑这个看效果） |

管理命令：

```powershell
Get-ScheduledTask -TaskName "CampusNetLogin*"          # 查看
Start-ScheduledTask -TaskName "CampusNetLogin_1800"    # 立刻测试一次
```

注意事项：
- 任务是「用户登录时运行」，**电脑必须处于已登录状态**（锁屏可以）；关机状态下没人能拉起浏览器。
- 勾选 `-Wake` 才能唤醒睡眠的电脑，但睡眠中的网络本身也不通，先确认你的场景需要。
- 睡眠/休眠时校园网往往已经掉线，唤醒后认证才有意义。

### 方案 C（可选）：让电脑别睡

若希望 24 小时保持在线，还得让系统不进入睡眠：
`powercfg /change standby-timeout-ac 0`（接通电源时永不睡眠），或把电源计划里「睡眠」设为「从不」。

## 认证页地址怎么找（以及为什么通常不该填）

**先判断你的门户是哪种**：

| 情况 | 该怎么做 |
| --- | --- |
| 地址里带 `sessionId`、`userIp`、`userMac`、`wlanuserip`、`ac_id` 等**每次都会变**的参数（安工程就是这类） | 用「**让网关自动跳转**」，别填地址。填死了下次就失效 |
| 地址固定、直接访问就能看到登录框（如 `http://192.168.1.1/login`） | 可以选「直接打开认证页地址」并填上 |

找地址的方法（只是想看看的话）：未认证状态下随便打开一个 **http** 网站，浏览器会被跳到认证页，复制地址栏完整地址即可。

## 高级：接口模式

门户是 ajax 提交（页面上没有普通 form）时，用 F12 → Network 找到登录请求，填到「高级」里：

- 请求地址：`http://10.0.0.55/eportal/InterFace.do?method=login`
- 请求体：`userId={{username}}&password={{password}}&service=internet`
- 成功关键字：接口返回里代表成功的那段文字

开启后扩展不打开网页，直接在后台发请求。**这类门户的密码通常带 MD5/AES 加密，需要你先把加密后的值构造好**，扩展只负责发原始请求。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 时间点到了但没反应 | 看弹窗「下次认证」时间对不对；暂停过就先「恢复定时」；`edge://extensions` 里点该扩展的 Service Worker 看日志 |
| **跳到 serviceSelection「服务选择」页后不动了** | 1.8.0 已修：这一页是**独立整页、没有密码框**，旧版所有启动入口都以「有密码框」为前提，到了这一页脚本什么都不做。现在把它当成独立的进场点（URL / 页面文案 / 运营商选项三选一即可认出），页面自己会选服务并点确定；后台还会兜底补一次指令。若仍不动，弹窗底部的**页面诊断**里会带页面骨架，发过来就能定位 |
| **停在 serviceSelection「服务选择」页、什么都不发生** | 1.9.0 已修，两层原因：① 找「确定」时把包着两个按钮的 `<div class="footer">` 当成了按钮，点不在真正的 `<button>` 上，门户收不到；② 包着三家运营商的容器被当成「中国电信」的候选，点在了容器上，运营商一个都没选中。现在容器降权、候选只认「只出现一家」的元素。若仍不动：看弹窗状态里有没有「停在『选择服务』页面但扩展没有操作：…」——那句话会直接说明是哪个开关挡住了 |
| **卡在「请选择服务」界面不动** | 1.7.0 起改成「能点的全点一遍」：radio / label / 文本元素 / **逐层往上点祖先容器** + **整页粗搜**兜底。若仍卡住，点开扩展图标，弹窗底部会显示**页面诊断 + 一段原始 HTML**（点一下复制），发过来就能直接定位 |
| **跳转慢、点了半天没反应** | 1.7.0 起探测请求每个地址最多等 1.5 秒、连挂两个就收手，不再一路挂着等 TCP 超时；等页面就绪也不再多轮注入脚本 |
| **到点了，门户却直接显示「已在线」页（认证还没到期），什么都没发生** | 1.11.0 起会先点「我要下线」+ 确认弹窗，等门户注销跳回认证页后**把整套认证重做一遍**（认证时长这才从这次续上）；若注销后落到「已下线」页，会点「重新入网」回到认证页（认不出那个入口还会照门户自己的做法跳到重新入网地址）。前提是设置里「已在线时先下线再认证」开着（默认开）；关掉即退回旧行为——认成「本来就在线」直接跳过，一个按钮都不碰 |
| **点了认证却一个网页都不开，只说「本次无需认证」** | 认证没到期时网络本来就通，后台以前拿这一句就收手、连页面都不开，页面脚本没机会干活（1.12.0 修的就是它）。现在探测结论只用来找门户地址：定时开着续期、或手动点「保存并立即认证一次」，都会真的把门户页打开（已认证时还跳过网关检测地址，直接进门户自己的页面）。只有「页面怎么都刷不出来 + 再探一次确实通」时才会悄悄关掉标签，不留垃圾窗口 |
| **注销完停在「已下线」页不动 / 认证没进到网页里** | 1.11.1 已修：门户那个入口的 i18n 是 `Reconnect.network`，**真实中文是「重新入网」**，1.11.0 误写成「重新连接网络」，真机上一次都没认出来。现在词表照门户语言包抄齐；**万一门户改版认不出、或点了没反应，还会照门户自己的做法跳到它的重新入网地址**（`localStorage.samPortalRedirectUrl`，兜底 `协议//2.2.2.2`），所以「没点『重新入网』也照样进认证网页」 |
| **认证早就好了，通知/关页面却慢半拍** | 1.10.0 起**跳转到最终界面就算完成**：点过「确定」之后只要离开登录页/服务选择页就立刻收尾，不再等「成功字样」或网络探测（原来这里要等满 6 秒观察窗 + 一次探测）。前提是这一版已被加载，见下面的「重新加载」 |
| **明明没网，却说「无需认证」** | 1.6.0 已修：只有 204 才算已联网，网关回的 200 拦截页不再被当成联网。现在这种情况会照常打开认证页；急用时也可以直接点弹窗里的 **打开认证页** |
| **服务还没选完，认证页就被关了** | 1.6.0 已修：「成功」判定从「没有密码框 + 页面出现已连接/注销」收紧为「明确成功字样 + 弹窗和确定按钮都已消失」，判定不出来时还要 204 探测点头。诊断里能看到 `radio=3(选中0)` 这类现场 |
| 打开的页面**没有登录表单** | 说明这个入口缺参数或地址过期。扩展会自动换下一个入口（自带参数的 → 备用入口 → 手填地址 → 网关跳转）；都刷不出来时弹窗会列出试过的地址 |
| 状态一直「需认证」但能上网 | 探测地址被学校屏蔽，设置里点「测试这些地址」换一个，或把「放宽探测判定」打开 |
| 找到认证页但没填 | F12 查输入框 id/name，填进「页面元素选择器」 |
| 认证成功但页面关得太慢 | 1.10.0 起只要门户跳转到最终界面就立刻关页（通知排在关页之前发出）。确认「认证成功后关闭自动打开的认证页」是开着的；若门户是先跳 `redirectUrl` 再出结果，也会在跳转那一刻就收尾，不再等探测 |
| 认证页在 iframe 里 | 已支持（内容脚本注入所有子框架）；仍失败就把 iframe 那层地址填成认证页地址 |
| 提示需要验证码 | 图形验证码无法自动识别，需手动认证一次 |
| 提示认证失败 | 学校可能限制同时在线设备数、或需要先选运营商，接口模式下补上对应参数 |
| 用的是**客户端软件**（锐捷/深澜客户端、802.1X） | 这种不走网页认证，浏览器扩展无能为力，需要客户端或系统层面方案 |
| 计划任务没运行 | `Get-ScheduledTask -TaskName "CampusNetLogin*"` 看状态；确认电脑处于已登录状态；用 `Start-ScheduledTask` 手动触发排查 |

**① 页面流程测试**（jsdom 复刻真实门户，136 项断言）

门户的服务商选项按四种真实结构各复刻一遍，并且**未选服务时「确定」是禁用的** —— 这正是「卡在选择运营商界面」的成因。

| 场景 | 验证点 |
| --- | --- |
| A 一次成功 | **radio 真的被选中**（`dx`）；登录按钮初始禁用，填值后能否激活并提交 |
| B 失败两次后成功 | 走「我知道了 → **重新选服务** → 确定」；**从未点「重新登录」**；账号密码只提交 1 次 |
| C 一直失败 | 3 轮重试后停手报 failed，`确定` 不超过 6 次，不误报成功 |
| D 失败后服务弹窗短暂消失再恢复 | 会等按钮出现再点，不空点、不误判失败 |
| E **页面自己动手** | 后台从不下发指令，页面读到配置后照样完成整套认证 |
| F **晚渲染的密码框** | 密码框延迟出现，仍能在极短时间内被抓到并填写 |
| G 老式 `button` 结构的门户 | 两种门户结构都要能选 |
| H **「确定」一直禁用** | 不空转到超时、不误报成功，失败结论里**带上页面诊断** |
| I **点了「确定」毫无反应** | 自动重新选服务再提交，最终成功（卡住自愈） |
| J **页头挂着「已连接 · 注销」的干扰文案** | 不许因此判成「已连接」提前收尾：必须真的选中运营商、真的点过确定、真的等到成功页 |
| K **卡片式服务选择** | 单选框和文字都被 `opacity:0` 藏进卡片、弹窗连标题都没有：仍要认出「这就是服务选择界面」并选中、提交 |
| L **纯列表式服务选择** | 没有 radio、文字很长（长到不会被当成候选）、**只有整行容器本身能被点中**：必须靠「逐层往上点容器」这条兜底路径选上 |
| N **这个框架里没有登录表单** | 指令是往整个标签页广播的，没有表单的框架必须直接让开，**一条结论都不许回报**（否则会变成一条假的「认证失败」） |
| P **服务选择独立页（无密码框）** | 复刻真实的 `…/entry/pc/serviceSelection;flowParams=…` 整页：没有登录视图、没有密码框。后台下发指令也要能**直接选中运营商并点确定**，绝不能误填/误交账号密码 |
| Q **服务选择独立页 + 卡片式** | 同一页但选项被 `opacity:0` 藏进卡片；**全程没有后台指令**，页面自己动手也要能选上并确定 |
| R **真实门户结构（ng-zorro，整页无 radio）** | **从门户前端代码里抠出来的真实结构**：`.service-box > span.service`、「确定」是 `.footer` 里的 `button.button-6`（未选中时 disabled）、文案全走 i18n。页面自己动手也要能选中并确定 |
| R2 **真实门户结构 + 后台指令** | 同上，但由后台下发指令进场：两条路径都要能选中并提交 |
| S1 **真实结构 · 没填认证页地址** | 只能靠页面特征认门户：不许把这一页挡在门外 |
| S2 **真实结构 · 运营商是空的** | 不许因此原地不动（退到默认运营商试一次） |
| S3 **真实结构 · 扩展被关掉** | 门禁真挡住时**不许静默不动**：必须给一条能看懂的说明，也不许把它伪装成一条「认证失败」 |
| T **点确定后跳到最终界面** | 落地页**一个「成功」字样都没有**：只要地址真的跳走、流程 UI 没了，就必须**立刻**算完成（点确定到收尾 < 1.5 秒），不再等成功字样或网络探测 |
| U **落地页文案带「已选择服务 中国电信」** | 不能用文字判定「还在选服务页」：只认硬信号（地址 / 密码框 / 可见的确定按钮 + 服务选项） |

| W **提交后被送回登录页** | 地址是变了，但那不是最终界面（还有密码框）：**不许**当成功、不许点「重新登录」 |
| X **到点时门户直接给「已在线」页** | 复刻 `app-login-success`（`entry/pc/finish;flowParams=undefined;from=`）：**必须先点「我要下线」+ 确认弹窗的「确定」**（不许点「取消」），等门户注销跳回认证页后**把选服务 + 确定整套重做一遍**，最终认证成功；并且要向后台报 `relogin` 标记 |
| X2 **同上，但由后台下发指令进场** | 两条进场路径（页面自启动 / 后台指令）都必须走完「下线 → 重新认证」，行为一致 |
| X3 **下线后落到「已下线」页（真机链路）** | 注销完门户不是回认证页、而是换成「已下线」页（SPA 换视图，脚本不会重新注入）：必须点「重新入网」回认证页再认证。这一页是**等注销动作完成后才注入 DOM** 的，不跟着一起渲染 |
| Y **已下线页 · 门户真实文案** | 入口文字按门户语言包写**「重新入网」**（不是意译的「重新连接网络」）：必须点中它回到认证页再认证；**不许**把这一页当成「已在线」去点「我要下线」；入口点得到时不许乱跳 |
| Y2 **已下线页没有那个入口** | 门户改版/接口挂了：必须**自己跳到门户的重新入网地址**（优先 `localStorage.samPortalRedirectUrl`），而不是原地死等或报失败 |
| Y3 **入口在、点了没反应** | 点了但页面纹丝不动：仍要有跳转兜底，认证继续 |
| Z **关掉「已在线时先下线再认证」开关** | 结果是 `skipped`（本来就在线）：**一次都不许点「我要下线」**、不许点任何确认弹窗 |

> 场景 R/R2/S1/S2/S3 是「依旧选择服务界面不动」在页面侧的原型。这一组不再靠自编结构，而是**直接把门户前端代码（`ServiceSelectionModule`）里的模板抠出来复刻**：

>

> 那一页的按钮 i18n 是 `Reconnect.network` —— **语言包里的真实中文是「重新入网」**，
> 点它执行的是 `window.location.href = localStorage.samPortalRedirectUrl || 协议 + '//2.2.2.2'`（chunk 7243 / 9903 / 4457）。
> 这一组最容易踩的坑是**判据互相包含**：已在线页的功能卡片里**有一项就叫「选择服务」**（会把服务选择页的判定骗过去），

> 旧版 v1.11.1 在新增的「认证也要进入网页」三条场景上 **85/96 全挂**（11 个失败项正好是 23a/24/25）——
> 因为后台当时一看网络通就一句「本次无需认证」收手、**一个页面都不开**，
> 页面脚本连出场的机会都没有，那条「已在线 → 下线 → 重新认证」的支路永远跑不到。
>
> ⚠ Windows 上用环境变量指旧脚本时，路径要写 **Windows 形式**（`C:/…/regress-v1.11.0-content.js`）——
> Git Bash 里的 `$PWD` 是 `/c/…` 形式，Node 在 Windows 上解析不到，会**静默回落到当前脚本**、
> 于是「旧版」跑出和新版一样的结果，对照就白做了（这台机器上已经踩过一次）。
